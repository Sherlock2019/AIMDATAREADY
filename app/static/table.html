Readiness gate for AI agents

Is this data fit for this AI task, for this user and this agent, right now?

Task Data Readiness runs before an AI agent touches supply-chain data. It checks that the data a task needs is authorized, current, complete, traceable and under contract. Then it either releases only the authorized data, or explains exactly what is missing, why, and how to fix it.

The problem

AI agents answer confidently, even when their data is wrong for the job

Generic data-quality tools check a dataset in general. This gate checks fitness for this task, this user and this agent at the moment of use.

Without a gate

  • ✗Stale stock levels, so the agent recommends the wrong transfer
  • ✗Missing warehouses, lanes or periods, so the plan is incomplete
  • ✗Unknown units, codes or duplicate rows, so the numbers are wrong
  • ✗Data the user may not see (e.g. supplier prices) leaks through the agent
  • ✗Expired or superseded contracts quoted as if they were current

With Task Data Readiness

  • ✓Freshness measured against this task's limit: 2 h for a transfer, 48 h for a weekly report
  • ✓Rows must cover the requested product, warehouses, lane and period
  • ✓Contract quality rules checked on exactly the rows the task uses
  • ✓User and agent access checked separately; only permitted rows and columns are released
  • ✓Only approved, currently valid documents count, with citations
How it works

Detect, propose, fix: a guided loop that ends in certified data

Every AI task has a versioned, approved Data Readiness Profile: the data it needs and the rules that data must meet. The engine is deterministic and returns evidence for every check.

1Set the context

Who is asking, for which task, which data they and the agent may use, and the profile that task must meet.

2Check readiness

Every metric of every required source gets a value, a status, a recommended fix and a measured root cause.

3Fix and approve

Allow-listed fixes from the mock agent or Claude. Only the data owner approves; approved fixes become upstream rules.

READYCertified, published as a new version, indexed for RAG. The agent reads only that data.
How readiness is assessed

Every check the gate runs

Twelve checks, each tied to a source of truth in the repo or the data contract.

The verdict

Three possible answers, never a guess

READY

Every mandatory check passes. The data is released to the agent, limited to what this user may see.

READY WITH WARNINGS

Only optional data has issues. The task runs, and the answer says what was weaker.

BLOCKED

A mandatory check failed or could not be measured. Nothing is released; the gate lists what to fix.

How to use the demo

Six steps, about two minutes

  1. Pick a user role, then a task that role may request.
  2. Read Authorized data (allowed vs required) and the task's readiness profile.
  3. Choose a data set. It does not say whether it is faulty; the checks find out.
  4. Click Run checks: every metric shows its value, status, fix and root cause.
  5. If BLOCKED: Propose fixes, then Approve & apply. Fixes you may not approve go to the owner via Request approval.
  6. If READY: the data is certified and published, and you can ask the agent questions over only that data.
